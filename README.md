# ReadLab — 英语阅读教学辅助工具

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](./LICENSE)

ReadLab 是一个**纯前端、零依赖、可离线运行**的英语阅读教学辅助应用。它面向中学英语教师备课场景：把一篇英语文章粘贴进来，自动产出一份"可直接用于备课"的阅读分析报告，并把文章、分析结果、标注、生词沉淀成可复用的资料。

整个项目只有 HTML + CSS + 原生 JavaScript，不需要构建、不需要服务器、不需要联网，所有数据保存在浏览器本地存储（localStorage）中。

---

## 1. 项目解决什么问题

教师备一节英语阅读课，通常要手工做这些事：数词数、估难度、挑重点词汇并查释义、找出长难句、划分段落逻辑、设计读前读后问题。这些工作重复、耗时，而且很难在不同课文之间复用。

ReadLab 把这一套流程固化成一条流水线：

- **重复劳动自动化** —— 词数、句长、难度、词汇频次、长难句、段落结构由规则引擎直接算出来，不用手动统计。
- **分析结果可留存** —— 分析结果挂在"项目"下（年级 / 类型 / 主题 / 教学目标），下次教同一单元可以直接打开，不必从零重做。
- **阅读与备课打通** —— 同一篇文章既能做教学分析，也能进入标注视图逐词查释义、划词高亮、写批注，查过的词一键进生词本。
- **数据不出本机** —— 无后端、无账号、无网络请求，文章与备课资料只存在本机浏览器里。

> 说明：分析由**本地规则**完成（词频统计、停用词过滤、句长阈值、信号词匹配等），不是大模型语义理解。它能稳定复现、完全离线，但不会"读懂"文章含义，具体边界见 [§7 局限与边界](#7-局限与边界)。

## 2. 主要功能

应用共 5 个页面：首页、阅读工作台、阅读标注、个人生词本、资源中心。

### 2.1 首页

- 统计卡片：项目总数、最近使用条数、可用功能数、累计词数、已保存的分析结果数。
- 最近使用列表（最多显示 6 条，记录上限 20 条），点击可跳回对应页面。
- 五大功能入口卡片，点击直接进入工作台并选中该功能。
- "新建项目"弹窗：填写项目名称、年级、文章类型、主题，创建后直接进入工作台。
- 顶部显示当前日期与星期。

### 2.2 阅读工作台（核心）

输入文章 + 选定教学上下文，运行五种分析之一。

| 功能 | 实际做的事 | 关键参数（与代码一致） |
| --- | --- | --- |
| 📊 文章基础诊断 | 输出 10 项指标 + 一段难度建议 | 长句阈值 ≥20 词；阅读速度按 200 词/分钟；难度分 基础 / 中等 / 较高 |
| 🔑 核心词汇筛选 | 去停用词后按词频排序，附本地词典释义 | 词长 ≥2；取 Top 20；显示前 8 个为标签；词典 334 条 |
| 🧩 长难句识别 | 按句长挑出长句，高亮从句引导词 | 阈值 ≥18 词；按长度降序取前 8 句；20 个从句引导词 |
| 🏛️ 文章结构分析 | 逐段提取首句摘要、关键词、逻辑信号词，推断段落角色 | 需 ≥2 段（空行分隔）；6 类信号词；结构框架按段数推断 |
| 📚 教学资源生成 | 生成课前导入、读中任务、读后讨论、活动与作业建议 | 使用主题、教学目标、Top 10 高频词（≥3 字母） |

各功能的判定细则：

- **难度判定**：平均句长 > 22 词 或 长句占比 > 0.4 → `较高`；平均句长 > 15 词 或 长句占比 > 0.2 或 词汇丰富度 > 60% → `中等`；其余 → `基础`。
- **结构框架**：2 段 → `总分`；3 段 → `总—分—总`；≥4 段 → `总—分—分—总（多层展开）`。
- **段落角色**：首段按文章类型给出（议论文"引入/提出观点"、记叙文"背景/开端"、其他"引入话题"），末段"总结/升华"，中间段按类型给"论证展开 / 情节发展 / 主体说明"。
- **逻辑信号词**分 6 类：转折、因果、递进、举例、总结、顺序。

工作台还支持：

- 粘贴/输入时**实时统计词数**。
- **保存当前**：把文章与上下文存成项目（不填项目名时，自动用"主题 + 阅读"或时间戳命名）。
- **保存本次结果**：把某一功能生成的报告 HTML 存进项目的 `features` 字段，下次打开项目自动回显。

### 2.3 阅读标注

- 输入文章后点"生成标注视图"，正文按段落渲染，**每个英文单词都被包成可点击单元**。
- 选中文字弹出浮动工具栏：黄色 / 蓝色 / 绿色高亮，或添加批注（批注内容同时作为鼠标悬停提示）。
- 点击任一已有标记可删除（需确认），删除后保留原文。
- **标注记录面板**：实时统计标记总数 / 高亮数 / 批注数；点击记录可平滑滚动定位到正文并闪烁高亮。
- **逐段总结**：每个段落一个文本框，输入后 600ms 防抖自动保存。
- **整篇心得**：单独保存、可清除。
- **项目关联**：下拉框在"草稿（未关联项目）"与各项目之间切换，标注数据按项目独立存储；关联项目时，文章与词数会同步回项目。
- **清除全部标注**：重置高亮、批注、心得与段落总结，但保留原文。

### 2.4 单词查询浮层

- 在标注视图中点击任意单词，弹出释义浮层（自动避让视口边界）。
- 内置离线词典命中则显示中英释义，未收录则提示可加入生词本后补充笔记。
- 支持**朗读**（浏览器 `speechSynthesis`，`en-US`，语速 0.9）与**一键加入生词本**（自动带上释义与该词所在句子作为例句来源）。

### 2.5 个人生词本

- 四项统计：总数 / 已掌握 / 学习中 / 未学习。
- 搜索框按单词或释义实时过滤。
- 每个词可：循环切换状态（未学习 → 学习中 → 已掌握）、添加备注（词性、记忆法、例句）、删除。
- **复习模式**：从所有非"已掌握"的词中抽题，显示进度百分比，支持上一词 / 下一词，答题时可直接标记"已掌握"或"学习中"。
- **打印生词表**：新窗口生成带表格的打印页并调用 `window.print()`。
- 空态下提供"手动添加生词"，输入单词后自动查词典补释义。

### 2.6 资源中心

- 列出所有已保存项目，显示年级 / 类型 / 主题标签、已保存的功能结果标签、词数与更新时间。
- 按关键词（项目名 / 主题 / 正文）、年级、类型三重筛选，并显示命中数量。
- 每个项目三个操作：**打开分析**（进工作台）、**去标注**（进标注视图）、**删除**（需确认）。
- "保存当前工作台内容"按钮：把工作台里的文章直接存成项目。

### 2.7 数据与交互细节

- 全部状态存于 `localStorage`，键前缀 `readlab_`：`readlab_projects`、`readlab_recent`、`readlab_vocabulary`、`readlab_annodoc_<项目ID|draft>`。
- 存储写入失败时降级为一条提示，不阻塞界面。
- 页面切换为单页视图路由（`home / workspace / annotation / vocabulary / resource`），从资源中心进入时显示返回按钮。
- 全部用户输入在渲染前做 HTML 转义。

## 3. 安装方法

**无需安装。** 项目没有 `package.json`，没有任何第三方依赖，不需要 npm / Node / 构建步骤。

### 方式一：直接打开（推荐）

进入 `dist/` 目录，双击 `index.html`，或拖进浏览器窗口。

`dist/index.html` 是**单文件成品**：CSS 与全部 JS 已内联，`file://` 协议下可直接运行。

### 方式二：本地静态服务器（可选）

```bash
cd readlab
python -m http.server 8080
# 浏览器访问 http://localhost:8080/dist/index.html
```

### 环境要求

- 现代浏览器：Chrome / Edge / Firefox / Safari 较新版本。
- 需要启用 `localStorage`（无痕模式下数据不会保留）。
- 朗读功能依赖浏览器语音合成；不支持时点击朗读会静默失败，不影响其他功能。

### 源码结构

```
readlab/
├─ dist/
│  └─ index.html          # 单文件成品（样式 + 脚本内联），直接运行这个
├─ css/
│  └─ style.css           # 全部样式（CSS 变量主题、布局、组件）
├─ js/
│  ├─ dictionary-data.js  # 内置离线词典 READLAB_DICT（334 条）
│  ├─ dictionary.js       # 点击查词浮层、朗读、加入生词本
│  ├─ features.js         # 五大分析功能的规则引擎
│  ├─ app.js              # 视图路由、localStorage 封装、项目/最近使用、新建项目弹窗
│  └─ views/
│     ├─ home.js          # 首页
│     ├─ workspace.js     # 阅读工作台
│     ├─ annotation.js    # 阅读标注
│     ├─ vocabulary.js    # 个人生词本
│     └─ resource.js      # 资源中心
├─ README.md
├─ LICENSE                # MIT 许可
└─ .gitignore             # 忽略临时文件、密钥与内部工作记录（.workbuddy/）
```

**注意**：仓库中没有构建脚本，`dist/index.html` 是把 `css/style.css` 与 `js/*.js` 手工内联后的产物。修改源码后需要同步更新 `dist/index.html`，否则直接打开看到的是旧版本。若要引用外部文件，请按以下顺序加载（存在依赖关系）：

```
dictionary-data.js → dictionary.js → features.js → app.js
→ views/home.js → workspace.js → resource.js → vocabulary.js → annotation.js
```

`app.js` 必须在所有 `views/*.js` 之前执行（视图在它创建的 `ReadLab` 命名空间上注册）。`ReadLab.init()` 的调用写在 `dist/index.html` 末尾的独立 `<script>` 里（所有脚本之后），因为 `app.js` 只定义方法、不自行启动。

## 4. 使用方法

### 4.1 一条完整备课流程

1. **打开应用** —— 双击 `dist/index.html`。
2. **填上下文** —— 进入「阅读工作台」，选年级（七年级~高三）、文章类型（记叙文 / 说明文 / 议论文 / 应用文），填主题（如"环境保护"）和教学目标（可留空，留空时用默认描述）。
3. **粘贴文章** —— 粘进输入框。<u>段落之间用空行分隔</u>，否则结构分析无法分段。右上角实时显示词数。
4. **选功能 → 点"开始分析"** —— 也可以从左侧子菜单或首页卡片直接进入某个功能。结果面板支持单独"保存本次结果"。
5. **保存项目** —— 填项目名（如"Unit 3 环保阅读课"）后点"保存当前"，项目进入资源中心。
6. **去标注**（可选）—— 从资源中心点"去标注"，或直接在标注页选择该项目；生成标注视图后划词高亮、写批注、点词查释义、把生词加入生词本。
7. **复盘**（可选）—— 生词本里做一轮复习，或打印生词表发给学生。

### 4.2 各功能使用要点

| 想做什么 | 操作路径 | 注意事项 |
| --- | --- | --- |
| 快速判断文章难度 | 工作台 → 文章基础诊断 | 看"综合难度评估"与"诊断建议"两处 |
| 挑精讲词汇 | 工作台 → 核心词汇筛选 | 词频 ≥2 的词优先；显示"未收录"的词需自行补充 |
| 讲长难句 | 工作台 → 长难句识别 | 仅列出 ≥18 词且最多 8 句；<18 词的句子不会出现 |
| 梳理篇章结构 | 工作台 → 文章结构分析 | 必须空行分段；单段文章会提示无法分析 |
| 出一份教案骨架 | 工作台 → 教学资源生成 | 主题与教学目标填得越具体，生成的导入/讨论越贴合 |
| 精读批注 | 阅读标注 → 生成标注视图 → 选文字 | 重新点"生成标注视图"会**清空已有标注** |
| 查词 / 朗读 | 阅读标注中点击任意单词 | 词典未收录时显示提示，仍可加入生词本 |
| 背单词 | 个人生词本 → 开始复习 | 已掌握的词不进入复习队列 |
| 找旧备课资料 | 资源中心 → 搜索 / 筛选 | 关键词同时匹配项目名、主题、正文 |

### 4.3 数据管理

- 数据只在本机当前浏览器中；换浏览器、换设备、清理浏览器数据都会丢失。
- 删除项目不可恢复，只删项目本身，不会删除已生成的生词。
- 标注数据按项目隔离：草稿（`draft`）与每个项目各存一份。

## 5. 输入输出示例

### 5.1 示例输入

- **年级**：九年级　**类型**：议论文　**主题**：环境保护　**教学目标**：理解主旨、掌握核心词汇
- **文章**（3 段，段落间空行）：

```
Plastic pollution has become one of the most serious environmental problems in the world. Every year, millions of tons of plastic waste are thrown into rivers and oceans, which causes great harm to sea animals.

Although many countries have realized the importance of this problem, it is still difficult to solve it completely. For example, plastic bags are cheap and convenient, so people keep using them in their daily life. However, these bags need hundreds of years to break down, and they pollute the soil and water.

Therefore, we should take action right now. First, we can bring our own cloth bags when we go shopping. Second, we should sort our rubbish carefully so that more plastic can be recycled. In a word, small changes in our daily habits can make a big difference to the environment.
```

### 5.2 输出：文章基础诊断

| 指标 | 值 | 指标 | 值 |

| 总词数 | 137 | 不同单词数 | 102 |

| 段落数 | 3 | 长句数（≥20 词） | 1 |

> 诊断建议：文章难度中等，适合训练精读与猜词策略，建议配合核心词汇表与长难句拆解使用。
> 已选择年级「九年级」、类型「议论文」、主题「环境保护」；建议结合「长难句识别」功能重点讲解 1 个长句。

> 结构框架：总—分—总（共 3 段，文章类型：议论文）

| 段落 | 角色 | 首句摘要 | 逻辑信号 |
| --- | --- | --- | --- |
| 1 | 引入 / 提出观点 | Plastic pollution has become one of the most serious environmental pro… | — |
| 2 | 论证展开 | Although many countries have realized the importance of this problem, … | 转折、因果、举例 |

### 5.6 输出：教学资源生成（结构）

固定四个板块：**课前导入（Lead-in）** → **读中任务（While-reading）** → **读后讨论（Post-reading）** → **课堂活动与作业建议**。内容会嵌入主题、教学目标与高频词，例如：

- 导入：以「环境保护」为话题做 2-3 个英文词头脑风暴；据标题预测内容。
- 读中：任务链"略读找主旨 → 扫读定位细节 → 精读分析长难句"；圈出 `plastic / pollution / …` 猜词义。
- 读后：`How does the word "plastic" help explain the main idea?`、`What is the writer's attitude toward 环境保护?`
- 作业：用核心词造句 + 60 词读后感。


`status` 取值为 `unlearnt`（未学习）/ `learning`（学习中）/ `mastered`（已掌握）。

## 6. 技术实现

- **无框架**：原生 DOM 操作 + 事件委托，`ReadLab` 全局命名空间下分 `store` / `Projects` / `Recent` / `views`。
- **路由**：`ReadLab.navigate(view, params)` 切换 `.view` 的显隐并高亮侧边导航，不做 URL 变更，刷新回到首页。
- **持久化**：`localStorage` + `JSON.stringify`，键统一加 `readlab_` 前缀，读写均做 try/catch 兜底。
- **文本处理**：
  - 分词：`/[a-z]+(?:'[a-z]+)?/g`（仅英文，含缩写，如 `don't`）。
  - 分句：按 `.!?` 切分。
  - 分段：按空行（`\n\s*\n`）切分。
  - 停用词表 149 个，覆盖冠词、介词、代词、助动词与常见缩写否定形式。
- **安全**：所有插值经 `esc()` 转义 `& < > "`。

---

## 7. 局限与边界

这些是当前实现的真实约束，README 不夸大能力：

1. **规则驱动，非语义理解**：词汇"重要性"只看词频；"长难句"只看词数；"结构"只看段数、首句与信号词。模型不理解文章真实含义，也不做同义改述。
2. **只处理英文**：分词正则仅匹配英文字母；中文或其他语言的文章分析结果为空或失真。
3. **两处长句阈值不同**：诊断里的"长句数"按 **≥20 词** 计，长难句识别按 **≥18 词** 筛选，两者数量不一致属正常设计（前者是统计口径，后者是教学挑选）。
4. **结构分析强依赖排版**：必须用空行分段；段落合并在一起时，整篇会被当成 1 段并提示无法分析。
5. **词典覆盖有限**：仅 334 条高频词，未收录词显示"—（未收录）"；释义为简写，不含音标、词形变化与例句。
6. **词汇不做词形还原**：`problem` 与 `problems`、`bag` 与 `bags` 分属不同条目，词频被拆散。
7. **难度评估是启发式**：仅由平均句长、长句占比、词汇丰富度三项加权判断，不等同于 Lexile / CEFR 等分级体系。
8. **数据不跨设备**：无账号、无云同步、无导入导出（生词表仅支持打印，不导出文件）；清缓存即丢失。
9. **不支持文件导入**：不能直接读 docx / pdf / txt，需手动粘贴文本。
10. **单文件分发需手工同步**：`dist/index.html` 为内联产物，改源码后必须同步，仓库内无自动化构建。

## 8. 后续可扩展方向

- 加一层轻量构建（如 esbuild / 简单 Node 脚本）自动把 `js/` 与 `css/` 内联进 `dist/index.html`，消除手工同步。

- 词典扩充词形还原（stemming）与音标字段。
- 长句分析加入"主谓宾"结构标注，而不只是引导词高亮。
